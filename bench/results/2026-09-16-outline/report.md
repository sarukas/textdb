## Accuracy checks (untimed)

These run outside every timed span, before and after each cell. They exist so a backend cannot post good latencies for work it did not do. **A cell that fails any check publishes no timings at all** — its latency rows are withheld and counted under `timings voided`.

| check | what it proves | textdb-sqlite | textdb-pg |
|---|---|---|---|
| clean_start | store empty before the suite ran | 3 pass | 3 pass |
| canary_roundtrip | create → read → delete round-trip | 3 pass | 3 pass |
| listed_readable | every listed document readable | 3 pass | 3 pass |
| size_consistent | listed size equals bytes read | 3 pass | 3 pass |
| storage_nonzero | documents stored, storage reported | 3 pass | 3 pass |
